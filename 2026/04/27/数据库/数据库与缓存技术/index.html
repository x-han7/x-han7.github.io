4. 相关面试真题

  • 典型问题:

    • Docker环境下PostgreSQL性能优化策略
在使用 Docker 部署 PostgreSQL 时，可以通过多种手段优化数据库性能

答案：

  1. 内存分配：
    • shared_buffers：配置 PostgreSQL 使用的内存量。建议设置为总内存的 25%-40%。
    • work_mem：配置查询操作（如排序和连接）使用的内存大小。在数据处理较多的查询中，适当增大这个值可以提高效率。
  1. 缓存策略：
    • Docker 容器限制：确保 Docker 容器拥有足够的内存资源，否则 PostgreSQL 的缓存机制可能受限。
    • 使用 Redis 来缓存热点数据，以减轻数据库的负担。
  1. 存储优化：
    • 挂载本地卷：将数据库文件挂载到主机上的 SSD 磁盘，从而提升数据读写性能。
    • I/O 限制：确保 Docker 没有对容器的 I/O 进行过多限制，否则可能影响数据库性能。
  1. 连接池管理：
    • 使用 pgBouncer 作为连接池管理工具，减少数据库连接建立和断开的开销，提高并发性能。
  1. 调优参数：
    • max_connections：根据容器资源合理设置连接数。
    • effective_cache_size：设置数据库的缓存容量预期，通常设置为主机内存的 50%-75%，帮助优化查询计划。
- 大型项目中TypeORM的应用实践
详细说明如何在大型项目中使用 TypeORM 进行数据库管理，及其对性能和维护的影响

答案：

TypeORM 是一个支持 TypeScript 的 ORM 框架，可以大幅提高数据库操作的开发效率。但在大型项目中使用时需要注意性能和维护的影响。

  1. 数据库表实体定义：
    • 通过 TypeORM 的装饰器（如 @Entity、@Column 等）来定义数据库表的实体结构。这种方式便于开发者理解数据模型，但需要注意实体定义的复杂度。
    • 在大型项目中，建议将实体与业务逻辑分开，以便于代码的模块化管理。
  1. 查询优化：
    • Lazy Relations 和 Eager Relations：使用 Lazy Relations 可以减少不必要的关联查询，适合需要按需加载关联数据的场景。而 Eager Relations 可以简化需要频繁关联查询的数据操作。
    • QueryBuilder：TypeORM 提供了 QueryBuilder 以支持复杂查询场景。通过 QueryBuilder 可以对查询进行更精细的控制，并进行性能优化。
  1. 数据库迁移管理：
    • 使用 TypeORM 的 migration 功能管理数据库表的变更，特别适合多开发者并行开发的场景，可以确保数据库的版本一致。
    • 在大型项目中，数据库变更频繁，使用 migration 可以自动化变更管理，但需要确保迁移脚本的可重性和测试。
  1. 性能影响：
    • 增加 load（Lazy Loading）：在有大量关系表的情况下，增加 load 可能会导致 N+1 查询问题，影响性能。应当通过性能监控工具（如 APM）发现并优化。
    • 批量操作：尽量使用批量插入和更新操作，避免逐条处理，以提升数据库的操作效率。
- Redis持久化机制对数据一致性的影响
Redis 提供两种持久化机制：RDB（Redis Database File）和 AOF（Append Only File），它们各自的特性对数据一致性有不同的影响

答案：

  1. RDB（快照）持久化：
    • 原理：定期将数据以快照的形式保存到磁盘中，备份间隔可以配置，但通常为秒级或分钟级。
    • 数据一致性影响：如果 Redis 崩溃，可能会丢失最近一次快照后的所有数据。对于高频更新的数据，这种方式存在一定的数据丢失风险，但性能较好。
  1. AOF（追加文件）持久化：
    • 原理：通过将每次写入操作记录到日志中，Redis 可以在重启时重新执行日志中的命令以恢复数据。
    • 数据一致性影响：AOF 具有更高的数据一致性保障（特别是设置为 always 或 everysec 模式时），但会对性能有一定的影响，特别是在高并发场景下，AOF 会增加磁盘 I/O 压力。
  1. 在生产环境中平衡性能与一致性：
    • 混合持久化：Redis 4.0 及之后版本支持 RDB 和 AOF 混合持久化方式，可以减少 AOF 重写的时间并提供较好的数据一致性。
    • 复制和高可用：配置 Redis 主从复制（Master-Slave），并结合 Redis Sentinel 实现高可用性。在主节点出现故障时，可以自动切换到从节点，以保证数据可用性和一致性。
    • 合理配置持久化策略：在高性能要求的场景下，可以减少 AOF 的同步频率，如每秒持久化一次（everysec），以在性能和数据一致性之间取得平衡。

5. Docker与数据库环境

1）Docker基础概念

  • 核心优势:
    • 轻量级: 相比传统虚拟机启动更快，资源占用更少
    • 一致性: 保证开发/生产环境一致性，解决”在我机器上能运行”问题
    • 可移植性: 应用及其依赖打包为标准化单元，支持跨平台部署
  • 技术原理:
    • 通过操作系统级虚拟化实现资源隔离
    • 共享宿主机的操作系统内核
    • 采用容器化技术实现环境标准化

2）Docker Compose

  • 编排功能:
    • 通过YAML文件定义多容器应用
    • 支持服务依赖管理和启动顺序控制
    • 典型应用场景：同时部署PostgreSQL+Redis+Node.js
  • 实践价值:
    • 简化复杂应用部署流程
    • 确保服务间网络连通性
    • 方便进行服务扩展和版本管理

3）安装指南

  • Mac安装步骤:
    • 官网下载Docker Desktop
    • 拖拽安装到Applications
    • 启动后验证运行状态
    • 终端执行docker –version验证
  • 跨平台支持:
    • 支持macOS/Windows/Linux
    • 自动适配不同系统版本
    • 提供统一的CLI操作接口

二、Docker基础与数据库环境配置

1. Docker安装与配置

  • 环境适配问题：服务端开发涉及MacOS 15.0.1/14、Windows7/11、Linux(CentOS/Ubuntu)等多平台环境配置差异
  • Docker解决方案：Docker 采用操作系统级虚拟化技术，容器直接****共享宿主机内核，无需虚拟化完整操作系统。它将应用程序及其运行所需的依赖（文件系统、库文件、环境变量等）打包为轻量级容器镜像，从而在任何支持 Docker 的平台上实现”一次构建，到处运行”的环境一致性。
  • 安装方法：
    • Mac：官网下载Docker Desktop的.dmg文件，拖拽安装到Applications
    • Windows：官网下载对应版本(AMD64/ARM64)的.exe安装文件
    • 验证安装：终端执行docker –version查看版本号
  • 核心优势：
    • 轻量级：相比传统虚拟机启动更快，资源占用更少
    • 一致性：开发/测试/生产环境完全一致，解决”在我机器上能运行”问题
    • 可移植性：应用程序与依赖打包为标准化容器单元

2. Docker核心概念

  • 三大核心组件：
    • Image镜像：包含极简系统+服务的静态模板，可从官方仓库获取或自定义
    • Container容器：镜像运行时的实例化对象
    • Volume卷：宿主机与容器间的文件绑定和持久化存储方案
镜像和容器的区别

Docker 容器和镜像是 Docker 最核心的两个概念，可以用一个类比来理解：

核心区别

详细解释

镜像 (Image)

  • 是一个分层构建的只读文件系统
  • 包含了运行应用所需的全部内容：代码、运行时、库、环境变量、配置文件
  • 类似于一个"快照"或"模板"，本身不运行任何程序
  • 可以从 Docker Hub 拉取，也可以通过 Dockerfile 自定义构建

容器 (Container)

  • 是镜像的运行实例
  • 在镜像的只读层之上，增加了一个可写层（容器层）
  • 容器内做的修改（如新建文件、修改配置）只影响这个可写层，不会改动原始镜像
  • 停止容器后，可写层的数据默认会保留；删除容器后，可写层数据随之消失（除非使用了 Volume 持久化）

关系图

┌─────────────────────────────┐
│      容器 (Container)        │  ← 动态、可读写、运行中
│  ┌───────────────────────┐  │
│  │    可写层 (容器层)      │  │  ← 容器内的修改都写在这里
│  ├───────────────────────┤  │

│  ├───────────────────────┤  │

│  ├───────────────────────┤  │
│  │    镜像层 1 (只读)      │  │  ← 基础镜像（如 Ubuntu）
│  └───────────────────────┘  │
└─────────────────────────────┘

    • 环境变量：数据库类服务必须设置认证信息

    • 连接类型：单机模式

      • 必须明确指定字段名和数据类型
      • 字符类型建议指定长度（如varchar(20)）
      • 多个字段用逗号分隔
    • 执行验证：执行后需刷新表列表确认创建成功
    • 表结构修改
      • 可视化修改：
        • 右键表选择”设计表”可修改字段属性
        • 注意：命令行创建的表可能限制可视化修改某些属性
      • 修改建议：
        • 字段长度等属性建议在创建时确定
        • 复杂修改推荐使用SQL命令而非可视化工具

  • pg可视化和命令创建表

    • 可视化建表流程
      • 操作步骤：
        • 选择”新建表”→”常规表”
        • 设置表名（如detail）
        • 添加字段：指定名称、类型、长度等属性
        • 可设置主键（如ID字段设为int4类型主键）
        • 保存完成创建
      • 优势：
        • 界面直观，降低初学门槛
        • 自动生成规范的SQL语句
        • 避免语法错误风险
    • 创建方式对比
      • 命令行创建：
        • 优点：灵活精确，适合批量操作
        • 缺点：需记忆语法，易出错
      • 可视化创建：
        • 优点：操作简单，所见即所得
        • 缺点：复杂操作受限
      • 学习建议：初学者优先使用可视化工具，熟练后逐步过渡到命令行

  • pg插入数据

    • 基本语法
      • 语法结构: INSERT INTO 表名(字段1,字段2) VALUES(值1,值2)
      • 自增字段处理: 当表中存在自增ID字段时，可以省略该字段的插入，系统会自动生成自增值
      • 字段选择: 只需指定需要插入值的字段名，如示例中的title和description字段
    • 具体操作示例
      • 示例数据1:
        • 字段：title和description
        • 值：(‘测试’, ‘111111’)
      • 示例数据2:
        • 字段：title
        • 值：(‘测试1’)
      • 执行方法: 框选SQL语句后点击运行，注意语句末尾必须加分号
      • 结果验证: 执行后显示”影响到了一行”，刷新表可查看新插入的数据
    • 注意事项
      • 分号要求: SQL语句末尾必须加分号，这是良好的编程习惯
      • 自增ID处理: 可以配置默认值为NULL，系统会自动处理自增逻辑
      • 批量插入: 可以连续执行多个INSERT语句一次性插入多条记录

  • pg查询数据

    • 基本查询语法
      • 全表查询: SELECT * FROM 表名，如SELECT * FROM detail
      • 字段选择: 可以指定只查询特定字段，如SELECT title FROM detail或SELECT description FROM detail
    • 查询结果展示
      • 全字段查询: 会显示表中所有字段的值
      • 单字段查询: 只显示指定字段的值，结果更加简洁
      • 结果验证: 执行查询后可以立即看到表中符合条件的所有记录

  • pg更新数据

    • 基本语法结构
      • 语法格式: UPDATE 表名 SET 字段名=新值 [WHERE 条件]
      • 核心操作: 通过UPDATE指定要修改的表，SET确定修改的字段和值
      • 注意事项: 必须明确要更新的具体行，否则会修改表中所有数据（如示例中未加WHERE条件导致全部title被改为”测试”）
    • 条件更新详解
      • 精确匹配: WHERE title=’测试一’（将title等于”测试一”的记录修改为指定值）
      • 模糊匹配: WHERE title LIKE ‘测试%’（使用LIKE进行模式匹配）
      • 多条件更新: 可通过AND/OR组合多个条件
    • 常见错误与修正
      • 错误示例: UPDATE detail SET title=value（缺少WHERE条件导致全表更新）
      • 类型问题: 注意字段类型匹配，如VARCHAR类型值需要引号包裹
      • 语法验证: 执行前检查等号、逗号等基本语法符号

  • pg查询与修改数据

    • 更新操作流程

      • 确定要更新的表名（FROM子句）
      • 指定要修改的字段和新值（SET子句）
      • 添加精确的WHERE条件定位记录
      • 执行前预览SQL语句
      • 执行后验证数据变更

    • 删除语法规范

      • 基本格式: DELETE FROM 表名 WHERE 条件
      • 危险操作: 省略WHERE条件将清空整个表
      • 与TRUNCATE区别: DELETE可回滚，TRUNCATE是DDL操作

    • 删除操作要点

      • 条件验证: 执行前先用SELECT验证WHERE条件匹配的记录
      • 备份建议: 重要数据删除前建议备份
      • 事务控制: 大批量删除建议使用事务

    • 结果验证: 每次增删改操作后都应刷新数据查看实际效果
    • 语法严格性: SQL不是自由编程语言，必须严格遵守语法规则

  • pg应用拓展

    • 文档型数据存储

      • JSONB类型优势：相比普通JSON类型，JSONB支持直接查询键值对，性能更好，是PostgreSQL特有的高级数据类型

      • 创建文档表：

      • 数据插入：JSONB字段需要插入标准格式的JSON字符串，可通过json.stringify()验证格式

      • JSONB操作演示

        • 基础查询：

          操作类型 SQL 示例 说明

          字段提取（对象） SELECT content->>'title' FROM docs; ->> 提取文本值，-> 提取 JSON 对象

      • 事务特性：ACID（原子性、一致性、隔离性、持久性）

      • 基本语法：

        • 通过 BEGIN和COMMIT或ROLLBACK控制事务。

        关键原则：事务中任一 SQL 执行失败，或业务条件不满足时，必须执行 <font style="color:rgba(0, 0, 0, 0.9);background-color:rgba(0, 0, 0, 0.03);">ROLLBACK</font> 撤销整个事务，确保数据不会出现”只扣款未到账”的中间状态。

      • 典型场景：电商下单流程（支付→生成订单→物流）必须保证要么全部成功，要么全部回滚

      • 错误处理：任一SQL失败时需执行ROLLBACK撤销整个事务

      • 它就像是你在数据库里自己定义的一个公式或小工具，可以把复杂的计算或重复的操作封装起来，随时调用。

      • 字符串函数：如LENGTH(title)可计算字段长度

        • 几何/网络地址等特殊类型

3. Redis应用

Redis 就像一个放在电脑内存里的“超级字典”，可以极快地存入、查找和取出各种格式的数据。Redis 用内存换速度，用简单数据结构换效率，作为数据库前的缓存层和高性能数据存储，专门处理读多写少、实时性要求高的场景。

1）Redis基础使用

  • 容器启动与连接
    • 容器状态检查：通过观察Redis容器状态指示灯是否为绿色确认运行状态
    • SQL文件导入：可通过”运行SQL文件”功能直接导入预先准备的SQL文件到数据库
    • Redis连接配置：
      • 单机版连接地址：localhost:6379
      • 认证方式：password（示例密码为”test123”）
      • 连接测试成功后即可开始查询操作
  • 基本数据类型操作
    • 字符串(String)操作
      • 设置值：set key value（如set name 测试）
      • 获取值：get key（如get name）
      • 注意事项：
        • 执行命令时需注意不要包含多余的分号
        • 未设置TTL(Time To Live)的值将永久存储
    • 哈希(Hash)操作
      • 设置字段值：hset key field value（如hset person name 哈哈哈）
      • 添加字段：可多次执行hset为同一key添加不同字段（如hset person age 18）
      • 获取字段值：hget key field
      • 获取全部值：hgetall key
    • 列表(List)操作
      • 左端插入：lpush key value（如lpush person:hobby ‘篮球’）
      • 右端插入：rpush key value（如rpush person:hobby ‘游泳’）
      • 获取范围内数据：lrange key start stop（如lrange person:hobby 0 1）
      • 获取长度：llen key
    • 有序集合(Zset)操作
      • 添加元素：zadd key score member（如zadd user 1 haha）
      • 特性：会根据score分数自动排序成员
  • 数据过期设置
    • 设置过期时间：
      • 单独设置：expire key seconds（如expire name 3）
      • 设置值时指定：set key value ex seconds
    • 应用场景：
      • 用户登录态管理
      • 协同文档中的房间状态管理
      • 消息广播的临时存储

2）Redis持久化

  • 持久化必要性
    • 内存数据易失性：服务器断电或宕机会导致内存数据全部丢失
    • 持久化解决方案：将内存数据定期保存到磁盘
  • 持久化方式
    • RDB持久化：定时生成数据快照
    • AOF持久化：记录所有写操作命令
    • 恢复过程：服务重启时从磁盘读取持久化数据加载到内存
  • 使用建议
    • 基础使用：掌握基本数据类型操作即可满足日常开发需求
    • 进阶内容：流(Stream)和消费组等高级特性可在实际项目中逐步学习

4. Node.js集成Redis和pg

1）创建项目并集成pg

  • 安装依赖：直接安装pg库即可使用PostgreSQL功能，安装命令为npm install pg
  • 连接配置：需要配置以下连接参数：
    • host：数据库主机名
    • port：默认5432
    • database：目标数据库名称
    • user：连接用户名
    • password：连接密码
  • 连接池创建：使用new Pool()创建数据库连接池，连接成功后可通过pool.connect()获取客户端
  • 查询执行：通过client.query()方法执行SQL语句，如SELECT version()或SELECT * FROM docs
  • 结果处理：查询结果包含rows属性，可通过result.rows获取查询结果集
  • 查询技巧：
    • 可使用JSON.stringify()格式化输出查询结果
    • 特定字段查询只需在SQL中指定所需字段名
    • 子查询可通过字段名直接访问，如children字段

2）创建项目并集成Redis

  • 安装依赖：安装redis库，命令为npm install redis
  • 连接配置：基本配置参数包括：
    • host：默认localhost
    • port：默认6379
    • password：连接密码
  • 客户端创建：使用createClient()方法创建Redis客户端
  • 事件监听：
    • on(‘error’)：处理连接错误
    • on(‘connect’)：连接成功回调
  • 数据操作：
    • 使用client.set()设置键值对
    • 可通过第三个参数设置过期时间，如EX 10表示10秒后过期
  • 连接验证：操作前需调用client.connect()建立连接
  • 实际应用：
    • 常用于存储用户会话信息
    • 设置过期时间可自动清理过期数据
    • 操作结果可通过Redis客户端工具验证

5. 对象关系映射

1）对象关系映射应用示例

  • 定义：ORM(Object-Relational Mapping)是定义数据库表和程序对象之间映射关系的技术，全称为**Object-Relational Mapping**。
  • 映射原理：数据库中的表字段与程序中的实体类属性一一对应，例如数据库中的user表对应程序中的User实体类，包含用户名、密码等相同字段。
  • 自动建表功能：当配置好ORM框架后，若数据库不存在对应表，框架会根据实体类定义自动创建数据表结构。
  • TypeORM配置：
    • 使用typeorm、pg等包实现PostgreSQL数据库连接Redis 混合持久化
    • 配置数据库连接池参数：host(127.0.0.1/localhost)、port(5432)、username、password、database等
    • 支持多种数据库：MySQL、SQL Server、MongoDB等
  • 实体类注解：
    • @Entity标记实体类对应数据库表
    • @Column定义表字段属性（如ID、name、description、status等）
  • 数据操作：
    • 通过dataSource.manager.save(实体对象)可直接将对象保存到数据库
    • 无需编写SQL语句即可完成CRUD操作
  • 示例演示：
    • 创建Photo实体类后启动项目，自动生成photo表
    • 修改实体属性后重新编译执行，数据实时同步到数据库
    • 查询操作通过简单的方法调用实现（如dataSource.manager.find(Photo)）
